## Decisions
- KL1007 checks container and pod-level `resources`, pod `overhead`,
  `emptyDir.sizeLimit`, PVCs (also StatefulSet `volumeClaimTemplates`), `ResourceQuota`
  `spec.hard` and `LimitRange` limits. YAML ints and finite floats are valid, null is
  valid (Kubernetes reads it as zero), surrounding whitespace in strings is trimmed
  (`Quantity.UnmarshalJSON` does), booleans and `.inf` are reported. Help texts suggest
  the exact fix for `mb`/`GB`/`K`/`gi`/`MiB`/`cores`/`mcores`/`bytes` and for a space
  before the suffix.
- Validators (`kubelint_k8s::validation`): `is_dns1123_label`, `is_dns1123_subdomain`,
  `is_dns1035_label`, `is_qualified_name`, `is_valid_label_value`. They return the first
  error Kubernetes would list, as `ValidationError { part, kind }`, whose `Display` is
  Kubernetes' wording without the regex. No `regex` dependency.
- KL1008: names are checked only for kinds in `stable_api_version`, in their own group.
  Namespace uses a DNS-1123 label, Service a DNS-1035 label, RBAC kinds only the path
  segment rule (no `/`, `%`, `.`, `..`), everything else a subdomain. `metadata.namespace`
  is checked on every object. Suggestions only for ASCII names. Long names are cut in
  messages by `rules::correctness::shown`, now shared with KL1010.
- KL1010 checks object labels, pod template labels (both CronJob templates), workload
  `matchLabels` (a ReplicationController's plain selector) and core Service selectors,
  not `matchExpressions`. It also reports label values YAML reads as numbers or booleans.
- KL1009 reports numbers and booleans in `env[].value` of every container kind; null is
  fine.
