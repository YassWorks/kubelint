## Decisions
- M1-11 split into M1-11a (YAML recovery) and M1-11b (KL0001). After a syntax error the
  parser restarts at the next `---` at column 0, starting with the error's own line
  (saphyr usually reports the error at the marker that ends the broken document).
- KL0001 is a registered rule with metadata only; the engine reports parse errors itself,
  whatever rules are enabled. M2-02 must keep it impossible to deselect (noted there).
- KL1001/KL1002 treat a null, `~`, empty or whitespace-only value like a missing field
  and stay silent on wrong types (schema territory, M4). Missing-field diagnostics point
  at the other type field, or at the object's first key when both are missing.
- `kubelint_k8s::stable_api_version(kind)` gives the GA `apiVersion` of built-in kinds for
  help texts.
- Human output: one snippet per file with all its labels, `= help:`, `= note: rule
  name`, and a summary like `Found 2 errors. Checked 3 files and 12 objects in 4ms.` The
  renderer gets rule names through a closure (layering).
- CLI: named files are linted whatever their extension; directories yield `*.yaml`/`*.yml`
  via `ignore` with `require_git(false)`; `--color auto` honors `NO_COLOR`; `fail-on` is
  fixed at `warning` until M2-02.

## Problems
- Inline `insta` snapshots still cannot be updated without `cargo-insta`: a wrong guess
  costs a cycle. Prefer file snapshots for anything longer than a few lines.
- `clippy::needless_raw_string_hashes` fires on `r#"..."#` explanations without quotes;
  use `r"..."` there.
- A Bash `cat > file` without a heredoc waits on stdin and hangs; use the Write tool.
