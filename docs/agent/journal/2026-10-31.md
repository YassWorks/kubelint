## Decisions
- Builder API is `parse(text) -> Parse { documents, errors }`. `saphyr-parser` repeats
  the same error forever after the first one, so parsing stops at the first error; earlier
  documents are kept, the broken one is dropped. This is what M1-11 (KL0001) builds on.
- Explicit `~`/`null` stay plain scalars; only missing values are `NodeKind::Null`. Typing
  is `Scalar::resolve_kubernetes()`.
- `get(key)` returns the last duplicate (Kubernetes decoder behavior); `entries()` keeps all.
- Range quirks: block collections start at their first child (not the `-`), block scalars
  start at their content (not `|`), alias nodes are clones of the anchored node with the
  anchor's range. Anchor/tag prefixes are skipped when computing node starts.
- Deviated from nothing in the roadmap order except doing M1-03 and M1-04 before M1-05
  (both were first-unchecked at their turn).

## Problems
- `saphyr-parser` was not in `Cargo.lock` until the first dependency was added; run a

- The scalar tables in M1-04 were written from memory of `gopkg.in/yaml.v2` `resolve.go`
  (no network access to the Go source). They should be diffed against upstream.
- The first CI run on a PR may show a failure for an older head after a follow-up push
