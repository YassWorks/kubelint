## Decisions
- M1-09 split into M1-09a (engine) and M1-09b (harness); M1-10 and M1-11 depend on
  M1-09b.
- `saphyr-parser` quirk: a quoted scalar's span runs over trailing spaces and a trailing
  comment. The builder now scans to the closing quote (#10). Comments after a syntax error
  are not reported (scalar ranges past it are unknown).
- `Object`, `PodSpec` and `Container` accessors return YAML `Node`s (with ranges), not
  strings. `objects(&Document)` expands `kind: List` into its mapping items and drops the
  wrapper.
- `pod_spec()` checks the API group (legacy `extensions` accepted, CRDs with a built-in
  kind name rejected), but falls back to the kind alone when `apiVersion` is missing or
  invalid, so container rules still run next to KL1001.
- Engine: `Linter::lint(&[SourceFile])`, `FileId` = index in the slice, output sorted by
  (file, offset, code). Contexts fill in the rule code and configured severity.
- The test harness has its own plain-text rendering (not the M1-12 renderer) so renderer
  changes do not churn rule snapshots. Test-only rules use codes `KL9xxx`, never allocated.

## Problems
- Inline `insta` snapshots cannot be filled without `cargo-insta` (not installed): use
  file snapshots, or write the inline value by hand.
- `git push --force-with-lease` fails with "stale info" when the remote session branch
  does not exist yet (deleted after merge); a plain `git push -u` works then.
