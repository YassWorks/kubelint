## Decisions
- KL1003: an object with no `metadata` key at all is reported only when its kind is a
  built-in one (`stable_api_version`), so `kustomization.yaml`, kubeconfigs
  (`kind: Config`) and component configs (`KubeletConfiguration`) stay quiet.
  `generateName` counts as a name.
- KL1004: identity is (API group, kind, namespace, name), version excluded. A missing
  namespace is its own value, not `default`. The finding is on the later `name:` entry
  with a "first defined here" secondary label, possibly in another file. Cross-object
  suppression is covered by the fixture (line) and a unit test (file).
- KL1005: one finding per failing `matchLabels` pair or `matchExpressions` item; missing
  selector, unknown operators and non-string values are skipped as schema problems.
  ReplicationController's selector is a plain map.
- KL1006: containers, initContainers and ephemeralContainers share one name set; "first"
  means first in the file.
- Quantity parser (`kubelint_k8s::Quantity`): follows `parseQuantityString`, except that a
  number without digits (`.`, `-`) is rejected (Kubernetes reads some as zero). Huge
  exponents are accepted and clamped, as Kubernetes parses them as `int64`.
  `QuantityError::InvalidSuffix` carries the bad suffix text for KL1007's messages.

## Problems
- Adding rules broke three tests that depended on the registry's size or shape: the
  `RuleSelection::resolve` doctest and a settings test selected the whole `correctness`
  category, and `rules_lists_every_rule` compared table spacing. All three now name
  rules explicitly or compare words. Two CLI tests now name their objects so KL1003 does
  not change what they test.
- Preparing the next PR on a local `wip-*` branch while CI ran, then moving it onto the
  new `main` with `git diff <old-base> wip | git apply --index`, avoided the conflicts
  that `git merge --squash` produced after a squash merge.
